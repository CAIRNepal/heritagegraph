# Implementation Plan: In-place submission edit (pre-filled + clear edit context)

**Branch**: `002-in-place-submission-edit` | **Date**: 2026-04-18 | **Spec**: `specs/002-in-place-submission-edit/spec.md`  
**Input**: Feature specification from `specs/002-in-place-submission-edit/spec.md`

## Summary

**Problem (observed in repo):** The knowledge **view** page’s **Edit** control navigates to `/contribute/<domain>` with **no record identifier** (see `heritage_graph_ui/.../knowledge/[domain]/view/[id]/page-client.tsx`). The shared **`OntologyForm`** only performs **POST** create and starts with an **empty** `formData` state—so the experience matches “new contribution,” not “edit existing record,” even when the user came from a specific item.

**Cultural entity** flows already have a **separate** pattern (`contribute/entity/edit`, `contribute/entity/revise`) that pre-fills from **URL-embedded JSON**; that is brittle for production (length limits, sharing, refresh) and is not the same as loading by **stable id** from the API.

**Direction:** Make “Edit” a first-class path: pass the **record id** (and domain) into the contribute flow, **GET** the authoritative record (same source as the view page), **map** API fields into `OntologyForm` state, show an explicit **editing** affordance (title, record id, status), and **PATCH** (or **PUT** where required) the same **CIDOC** resource the view page uses. Defer true **inline / click-to-edit-on-detail** (P3) until P1/P2 are solid, or add it as a thin layer that reuses the same load/save functions.

**Backend note:** CIDOC `ModelViewSet`s already support **update**; `ContributionFlowMixin` only customizes **create** permissions. Today **non-create** actions use **`AllowAny`** for `get_permissions`—tighten **update/destroy** to **authenticated + object-level rules** (contributor or staff) as part of this feature’s security bar.

## Technical Context

**Language/Version**: Python 3.13 (Django 4.x + DRF), TypeScript (Next.js 15 / React 19)  
**Primary Dependencies**: DRF `ModelViewSet` + project `apiFetchJson` / `getPublicApiUrl` patterns; ontology registry in `heritage_graph_ui/src/lib/ontology`  
**Storage**: PostgreSQL (CIDOC models + `heritage_data` CulturalEntity linkage from creates)  
**Testing**: `python manage.py test` (targeted `apps.cidoc_data` permissions/serializers if touched); manual + optional Playwright later for UI  
**Target Platform**: Web (Docker / Traefik as per repo)  
**Project Type**: Web application (Django API + Next.js App Router UI)  
**Performance Goals**:
- Edit screen shows a **loading** state until GET completes; avoid flashing an empty form as “ready.”
- Single-field edits: one PATCH with the payload the form already builds (no requirement for multi-round trips for P1).
**Constraints**:
- No secrets in repo; any new config in `.env.example` only.
- UI API base from `process.env.NEXT_PUBLIC_API_URL` / `getPublicApiUrl()` (no hardcoded `localhost` in new code paths).
- Protected writes use `Authorization: Bearer <session.accessToken>`.
- Ruff + TS build for touched code.
**Scale/Scope (initial deliverable)**:
- All routes that use **`OntologyForm`** for CIDOC create (ontology-driven contribute pages).
- **Edit** entry points from **`/knowledge/[domain]/view/[id]`** (and any table actions that should deep-link to edit with the same id).
- **Optional P3:** inline edit on the view page reusing the same **load**/**save** module.

**Structure Decision**: Centralize the **load + normalize + submit** path in `OntologyForm` (or a small `useOntologyRecordEditor` hook next to it) so all ontology contribute pages gain edit behavior without duplicating per-domain `page.tsx` files. Backend changes focus on **permissions** (and only serializer tweaks if read vs write shapes diverge).
